## 키비주얼 표시 옵션·미리보기 추가 (2026-10-20)

사용자가 키비주얼 문구와 앱 글자가 겹치고 읽기 어려운 문제를 제기한 뒤, 운영자가 표시 옵션을 조절하도록 요청했다.

- `theme_config.py`: `settings.key_visual` 검증. 표시 방식 split/background/poster, 제목·슬로건 표시, 제목 20~48px, 정렬, 글자/바탕 색상, 밝게/어둡게 덮개와 0~80% 강도, 위치 0~100%, 확대 100~200%, contain/cover, 원본 포스터 경로. 임의 CSS/HTML·외부 이미지 URL은 받지 않음. owner 권한과 잘못된 설정의 원자적 거부 유지.
- `public/theme-ui.js`: 앱 배경 `settings.hero`와 원본 포스터 `key_visual.poster` 분리, 로컬 blob 미리보기·모바일/PC·색상 대비·글자색 추천·적용/취소. 적용 전 업로드/저장하지 않으며 닫으면 blob 해제. 이미지 속 글자를 자동 제거하는 기능은 아님. 원본 포스터형은 이미지 전체 비율 유지, 앱 문구·필터·배치 효과 미적용.
- 기본값 split + 남색 글자. 기존 설정에 key_visual이 없어도 기존 배경·색상을 유지하며 기본 표시 적용. 행사 제목은 실제 event.name 사용; 기존 샘플의 ‘제22회’ 하드코딩 제거. 행사 복제 시 표시 설정 포함.
- `public/help-ui.js`: 설정 버튼 안내·비활성 미리보기 항목 제외. 튜토리얼 Esc가 배경 편집 팝업까지 닫지 않도록 키보드 전파 수정.
- 서비스 워커 v6에 theme-ui 캐시 추가. 외부 API나 새 라이브러리 불필요.
- 검증: Python 33개, Node GPS 9개 통과. 신규 `tests/browser-theme.cjs`는 미리보기 무저장·취소, 별도 업로드·잘못된 파일 거부, 3개 모드, 글자·필터·위치·저장, 원본 포스터, 구 설정 호환, 모바일/PC·튜토리얼·오프라인을 임시 DB/테스트 이미지로 확인. 전체 브라우저 실행기에 5번째 흐름으로 추가. 원격 Render의 새 버전 적용·실사용 포스터 반영은 수동 배포 후 별도 확인.

## 무료 테스트 배포 준비 추가 (2026-10-17)

사용자가 외부 접속 링크를 요청하고 ‘없음 — 무료 테스트 배포 기준으로 준비’를 선택했다. Render 공식 문서를 확인하고 루트의 `render.yaml`, `deploy_demo.py`, `docs/free-test-deployment.md`, `tests/test_deployment.py`를 추가했다. 테스트 전용 배포이며 원본 DB·계정·API 키는 복사하지 않는다. 관리자 이메일·비밀번호는 Render의 보안 환경 변수로 입력하고, 서버가 열리기 전에 최초 관리자만 생성한다. 기존 DB에서는 계정·데이터를 유지하며 외부 최초 관리자 생성은 비활성화한다. 무료 서비스는 재시작·휴면 시 DB와 키가 사라질 수 있어 실제 개인정보를 넣지 않는다는 안내를 모든 화면에 표시한다.

Render 계정 인증이나 배포 권한은 이 작업 환경에 없다. GitHub에 설정을 저장한 뒤 사용자가 배포 시작 링크에서 Render와 저장소 접근을 연결해야 실제 HTTPS 주소가 발급된다. Codex 환경 ‘게시’와 인터넷 앱 배포를 혼동하지 말 것. 실제 onrender.com 주소를 추측하거나 미배포 상태를 배포 완료라고 표현하지 말 것.

검증: Render 공식 JSON Schema로 `render.yaml` 검증 통과. Python 테스트 31개(배포 시작·인증·QR·재시작 3개 포함)와 Node GPS 테스트 9개 통과. 배포 시작 명령으로 임시 DB 서버를 띄운 Playwright 확인에서 모바일 홈·프로그램·테스트 안내·관리자 로그인·대시보드·가로 넘침·JS 오류 없음 확인. 최초 브라우저 시도는 로그인 버튼 이름을 잘못 지정해 실패했으며, 실제 ‘로그인’ 버튼으로 수정한 확인은 통과했다. Codex에서는 두 API 키의 이름·저장 여부·실행 환경 주입만 확인했고, 실서비스 호출은 하지 않았다. Render에는 키가 자동으로 전달되지 않는다.

## 유지할 핵심 결정

- 운영사가 여러 행사에 제공. 자유 출입·개인 참가, 예약 기능 제외.
- 참가 초기 개인정보 입력·기록 복구 제외. 같은 기기/브라우저 이용 안내.
- 운영자가 존 구성, 담당자가 존을 선택해 부스 등록. 부스당 QR 하나.
- 별점은 선택. 평가 없이 인증도 동일한 참여/미션 인정.
- 일시 중단·종료 시 서버에서 QR 인증 차단.
- 존 참여 인원 = 소속 부스별 참여자 합계. 부스 간 중복 제거하지 않음.
- 부스 담당자는 관리 QR+공통 비밀번호로 여러 명 동시 관리.
- 운영본부는 여러 개인 계정과 업무별 권한. 알림 확인 버튼·유형별 문의.
- 야외 길찾기, 실내 건물별 통합 평면도 한 장. 층 선택 없음.
- 하단 메뉴: 홈 / 프로그램 / 미션 / 안전 / 내 참여. 지도는 홈 바로가기.
- 미션은 신청/시작/모집 없이 수행. 부스 인증으로 반영, 별도 미션 QR 없음.
- 전체 설문 하나, 붙여넣기/표준양식 추가. 자격은 행사별 설정.
- 동일 연락처 최초 유효 응모 1건·중복 당첨 제외. 초기의 가족별 동일 번호 허용안은 폐기.
- 모바일 상품권 중심. 초기 외부 CSV 발송, 자동 API 미연결.
- 참가자/부스 탄소·지역경제 자료는 설문에서 수집. 근거 없는 감축·경제효과 수치 산출 금지.
- 키비주얼: 사용자 제공 제22회 대한민국 청소년박람회 포스터. 청록·파랑/분홍·노랑 포인트.
- 한국어/영어, 다른 언어 Chrome 번역 안내. 콘텐츠 번역 API 미연결.
- 안전·날씨·성희롱/불법촬영 신고. 민감 신고 별도 권한, 대응 체계 준비 전 비활성.

- 현재 `FESTIVAL_TRANSLATION_API_KEY`와 `FESTIVAL_KMA_API_KEY`는 미등록. 환경 설정에 등록할 요구사항 초안을 추가했고, 이는 키 입력/실행/게시 완료를 의미하지 않는다.
- 고급 산정·상품권 자동 발송·미성년자 동의·배포/부하 검증 등 전체 앱의 나머지 항목은 implementation-status.md를 확인한다.
- 실제 공급자 호출은 키가 없어 검증하지 않았다. 테스트는 대체 응답을 사용한다.
