## 2. 이번에 수정한 핵심 연결

### 행사 간 참가 기록

기존에는 전체 참가자 테이블에서 고유한 토큰을 여러 행사에 그대로 저장하려 해 두 번째 행사에서 충돌했다. 새 기록은 기기 쿠키와 행사 ID를 결합한 해시로 저장한다. 기존 방식의 토큰도 함께 조회하므로 이미 발급된 패스에 대한 DB 일괄 변환이나 초기화가 필요하지 않다. A→B→A 참여와 같은 행사 동시 요청을 검증했다.

### 기능을 끌 때의 의미

- **프로그램 끄기:** 참가자 메뉴·홈 프로그램·관심 일정 표시와 공개 프로그램 데이터를 제외한다.
- **미션 끄기:** 참가자 메뉴·홈 카드·부스 관련 미션·현재 진행 표시를 제외하고 답안 제출을 차단한다.
- **설문 끄기:** 새 접수와 진입 버튼을 제외한다. 이미 제출한 설문·응모 결과는 내 참여에서 확인할 수 있다.
- 기존 콘텐츠·답변·인증·당첨 자료는 삭제하지 않는다. 운영자는 설정과 기록을 관리할 수 있다.
- 미션을 끄면서 미션 달성을 설문/응모 조건으로 남길 수 없다. 운영자가 자격을 명시적으로 바꾸어야 저장된다.
- 새 행사에는 아직 생성하지 않은 미션을 응모의 기본 전제조건으로 두지 않는다. 기존 행사·복제 설정은 유지한다.

### 역할과 화면

서버에 있는 권한 기준에 맞춰 운영 메뉴·편집·QR 접근·분석·민감 신고 버튼을 표시한다. 행사 총괄과 플랫폼 전체 운영자를 구분해, 행사 개설 권한이 없는 담당자에게 개설 버튼을 노출하지 않는다. 일반 행사 총괄에게 피해지원 권한을 자동 부여하지 않는다.

분석 전용 역할 등에 불필요한 문의 대화와 발송 상세를 일괄 전달하던 응답도 제한했다. 이는 역할별 동작 점검이며 별도의 전면 보안 감사 완료를 뜻하지 않는다.

### 종료·보관·수정

- 현장 종료 행사에서는 새 신고를 접수하지 않고 긴급 전화 안내를 유지한다.
- 보관 행사는 공개 목록과 참가자 API에서 제외한다. 권한 있는 운영자의 관리 접근은 유지한다.
- 부스 종료 실적은 기존 답변과 숫자 0까지 다시 표시한다.
- 응답이 있는 설문도 비공개 전환·마감일 변경이 가능하다. 문항·제목·동의문을 바꾸는 요청은 거부한다.
- 담당자 권한 회수는 해당 행사 권한을 제거하고 기존 로그인 세션을 종료한다. 다른 행사 권한 자체를 삭제하지 않는다.

QR·설문·추첨·기본 문의·신고·지도·영어·날씨는 실제 필요와 기존 요구사항이 있는 기능으로 판단해 유지했다.

## 4. 사용자 선택에 따른 콘텐츠 수정·행사 준비 개선

이번 개선 전 사용자가 선택한 방향은 다음 세 가지다.

1. 콘텐츠 수정·행사 준비를 먼저 개선한다.
2. 안내 문구는 수정하고 이력을 보관하되, 참여 실적에 영향을 주는 조건은 제한한다.
3. 핵심 필수 항목 누락은 공개를 차단하고, 선택 기능 미설정은 경고한다.

| 미션·설문 → 미션 추가/수정 | 부스·존을 이름으로 선택. 새 미션은 기본 비공개. 비공개 준비 단계에는 유형·대상·목표·기간·퀴즈 조건 수정 가능 |
| 한 번 공개한 미션 | 제목·설명 수정 가능. 유형·대상·목표·기간·퀴즈 조건은 잠금. 다시 비공개로 바꿔도 잠금 유지 |
| 기존 달성자 보호 | 달성자가 있는 미션을 설문·응모 조건에 사용하는 동안 공개 중지 제한. 달성 가능한 미션 수가 필요한 완료 개수보다 적어지는 중지도 제한 |
| 공간·부스 → 존 안내 수정 | 이름·색상·소개 수정. 부스 연결·기존 인증은 유지 |
| 각 항목 → 변경 이력 | 이전/변경 내용·수정 담당자·시각 확인. 오래된 화면의 저장은 거부하고 갱신 안내 |

프로그램의 변경 안내도 영어 콘텐츠 검토 대상으로 포함했다. 취소한 프로그램은 새 행사로 복제하지 않는다. 공개된 미션의 새 조건이 필요하면 기존 미션을 덮어쓰지 않고 새 미션을 만든다. 저장된 인증·답변·관심 일정 데이터를 일괄 삭제하거나 재계산해 덮어쓰는 작업은 하지 않는다.

### 공개 준비 점검

운영본부 **대시보드 또는 행사 설정 → 공개 준비 점검**에서 저장된 행사 내용을 확인한다. 경고 항목에서는 권한에 맞는 설정 화면으로 이동할 수 있다.

- 항상 필수: 행사명, 장소(온라인 참여 장소 포함), 시작일·종료일과 날짜 순서.
- 사용 조건에 따라 필수: 앱 신고를 켰을 때 현장 연락처, 승인 부스의 인증 QR, 미션 자격을 선택한 설문·응모의 달성 가능한 공개 미션 수.
- 경고: 승인 대기 부스, 지도·보행로 미등록, 사용 중인 프로그램·미션·설문 미준비, 행사 기간 밖 프로그램, 활성화한 날씨의 지역·키 미설정.
- 공개/운영 상태로 저장할 때 서버가 최종 입력값으로 필수 항목을 다시 검사한다. 실패한 저장은 상태·설정 모두 반영하지 않는다. 선택 기능 경고만 있으면 공개할 수 있다.
- 화면은 저장된 자료의 준비 여부를 검사한다. QR 출력물 배치·실제 스캔, 현장 지도·GPS, 외부 공급자 응답, 백업·복구 완료까지 보증하지 않는다.

### 데이터 적용 방식

기존 콘텐츠 테이블과 참가 기록을 유지하고 `content_meta`, `content_history` 테이블을 추가한다. 기존 공개 미션은 시작 시 조건 잠금을 설정한다. 기존 항목의 과거 변경 내용을 복원해 만들지 않으며, 이번 기능 적용 후 수정부터 이전/변경 값을 기록한다. 이력 조회도 행사 범위와 콘텐츠/운영 권한을 검사한다.

### 퀴즈형·설문형 미션 추가 확장

사용자가 퀴즈의 제안 유형·자료·진행 방식을 모두 포함하도록 요청해 아래 범위를 추가 구현했다. 운영 기준은 필수 응답+필요 정답 수(기본 전부 정답), 힌트 선택 제공·제출 후 해설·무제한 재도전이다.

- 퀴즈 9종: OX, 단일 선택, 복수 선택, 단답, 빈칸, 짝 맞추기, 순서 배열, 상황 선택, 사진 속 위치.
- 자료: 텍스트·이미지·음성·영상·현장 관찰 안내. 사진 영역 지정과 파일 업로드/재생 연결.
- 진행 6종: 한 문제, 묶음, 단계별 공개, 무작위 출제, 답변 분기, 팀 협력.
- 팀 구성: 참가자 생성/코드 합류와 랜덤 배정을 동시에 제공. 팀원별 답안을 합산하고 정원·행사 범위·중복 제출을 검사한다.
- 설문형 미션: 단일/복수 선택·주관식·평가·숫자, 별도 완료·결과 집계. 행사 전체 설문과 분리하고 원자료 삭제 절차에 연결.
- 기존 단답형 퀴즈·참가 기록은 유지한다. 한 번 공개한 문항·정답·완료 기준은 잠그며 완료 기록을 이후 오답으로 되돌리지 않는다.

설정 위치·세부 정책·현재 한계는 [퀴즈·설문형 미션 사용 안내](mission-quiz-guide.md)에 정리했다.

## 5. 아직 미비하며 다음에 보완할 부분

아래는 이번 수정으로 완성됐다고 주장하지 않는 항목이다. 기존 기능을 삭제하기보다 의존 관계와 운영 정책을 먼저 정리해야 한다.

| 우선순위 | 미비한 연결 | 다음 작업 |
|---|---|---|
| 높음 | 실제 운영 데이터 보존 | 영속 DB·이미지·암호키, 별도 백업·복구, 검토/실운영 환경 분리 |
| 높음 | 외부 공급자 연결 검증 부족 | Render 환경의 번역·기상청 키, 행사장 격자, 지도 타일·현장 GPS 확인 |
| 중간 | 설문과 추첨을 별도로 켜고 끄는 설정 부족 | 응모를 하지 않는 순수 설문에서 연락처·추첨 UI 제외 |
| 중간 | 답변 수정·반려·재제출 흐름 부족 | 글 미션의 반려/재제출, 설문·연락처 정정 정책과 권한 정리 |
| 중간 | 부스 실적이 보고서에 항목별로 연결되지 않음 | 운영진 이동·구매·고용·숙박 등 응답 집계, 단위·중복 기준 표시 |
| 중간 | 시간대별 부스 집계 데이터는 있지만 차트 연결 없음 | 시간대 정의와 사용 목적 결정 후 연결. 현재 시간대 분석 기능으로 홍보하지 않음 |
| 중간 | 위젯·복제 후 데이터 입력의 실제 운영 검증 부족 | 실제 홈페이지 출처, 복제 행사 날짜·지도·부스·설문 점검, 일괄 입력 검토 |
| 중간 | 큰 행사에서의 성능·다중 편집 미검증 | 콘텐츠 수정 충돌은 차단. 행사 설정·부스·지도 등 다른 편집 영역과 실제 부하 검사는 후속 |
| 별도 정책 | 콘텐츠 삭제·공지 철회·공개 미션 조건 교체 | 수정·프로그램 취소는 구현. 연결 기록이 있는 자료의 삭제·이전 버전 복원·미션 조건 교체는 별도 정의 |
| 후속 | 상품권 자동 발송·예비 당첨·발송 실패 처리 | 우선 CSV와 공급자 결과 대조. 반복 수요 확인 후 API 연결 |
| 후속 | 사진 첨부·웹 푸시·예약 공지·재알림 | 저장·권한·전송 실패 처리까지 포함해 개별 개발 |
| 후속 | 탄소·지역경제 효과 산정 | 검증된 문항·계수·범위·방법론 확정 후 연결. 현재는 활동 자료와 실제 응답 합계만 제공 |
| 별도 정책 | 만 14세 미만 개인정보 설문, 기록 복구, 예약·좌석 | 현재 제한/제외 결정을 유지. 요구 변경 시 별도 기획 |

선택한 **콘텐츠 수정·행사 공개 준비**를 이번 단계에 반영했다. 다음 권장 순서는 **실운영 저장·외부 연결 → 부스 실적·종료 보고서**이며, 다음 구현 범위는 사용자와 정한다. 기능이 많아 보여도 다음 단계가 연결되지 않는 부분을 우선 해결한다.

## 6. 검증과 적용 범위

- Python 검사: 60개 통과. 기존 47개에 확장 퀴즈·설문·팀·원자료 삭제 13개를 추가했다.
- 전체 브라우저 검사: 기존 8종에 확장 퀴즈 검사를 추가한 9종 모두 통과. GPS 상태 검사 9개 통과.
- 신규 브라우저 검사: 최초 퀴즈 참여, 행사 간 패스 보존, 기능·신고 비활성, 미공개 설문, 중립 화면, 복제 미션, 보고서 전환, 부스 답변 복원, 권한별 버튼·회수.
- 콘텐츠 브라우저 검사: 필수 누락 공개 차단·경고만 있는 공개 허용, 프로그램 수정/취소·관심 일정·이력, 이름으로 미션 대상 선택·공개 후 잠금, 업무 알림 재확인·이전 확인 이력, 모바일 편집 화면.
- 확장 퀴즈 브라우저 검사: 9종 문항 작성/수정/미리보기/풀이, 이미지·음성·영상·현장 안내, 진행 방식 6종, 설문 작성·집계, 코드 팀과 랜덤 팀, 팀원별 공동 답안과 완료, 모바일 화면.
- 기존 브라우저 검사에는 첫 참여 안내가 생기는 시점과 설문 조회 완료를 명시적으로 기다리도록 수정했다. 오류를 숨기기 위해 검증 대상을 제거하지 않았다.
- 기존 GPS·지도·번역·날씨 검사는 모의 위치·대체 응답을 사용한다. 실사용 API 성공이나 현장 정확도를 보증하지 않는다.
- 수정 코드는 로컬 작업본이다. 원격 저장소 반영·Render 배포·환경 변수 변경·운영 데이터 변경은 수행하지 않았다.
