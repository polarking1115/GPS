# 다중 행사 운영 플랫폼 — 기능 명세 초안 v0.1

작성일: 2026-10-16 (Asia/Seoul)
상태: 기획 기준 문서. 이후 사용자의 제작 요청으로 로컬 개발 버전을 구현했다. 실제 동작·미연결 범위는 implementation-status.md와 README.md를 따른다. 이 문서는 전체 기능 완성을 의미하지 않는다.

## 1. 문서의 기준

- **확정**: 사용자가 명시적으로 선택하거나 수정한 요구사항.
- **추천**: 설명 과정에서 제시했지만 명시적으로 확정하지 않은 설계안.
- **미결정**: 출시 전 결정이 필요한 정책·기술·운영 사항.
- 사용자의 ‘다음 단계’는 앞선 모든 추천안의 일괄 승인을 의미하지 않는다.
- 참고 자료: 업로드된 2027.html. 화면·기능 아이디어 참고용이며, 그 안의 시뮬레이션 수치와 동작은 실제 구현 요건이나 검증 결과가 아니다.

## 2. 목표와 적용 범위

### 확정

- 운영사가 플랫폼을 직접 운영하고 여러 축제·박람회에 제공한다.
- 실내·야외 부스 체험, 전시, 여러 세미나실의 참여형 프로그램을 지원한다.
- 동시 체류 약 1만 명 규모를 고려한다. 앱 동시 접속 목표와는 구분한다.
- 자유 출입 행사이며 개인 관람과 학교·기관 방문이 혼재한다. 플랫폼 참여는 개인 단위다.
- 개인정보 입력은 참가자 설문 단계에서 진행한다. 초기 닉네임·생년월일 입력안은 폐기한다.
- 사전 예약 및 보호자·동반인 예약, 좌석·대기열 관리 기능은 제외한다.

### 추천

- QR·링크로 접속하는 모바일 웹 중심으로 제공한다.
- 행사별 데이터·권한을 분리하고 행사별 전용 주소를 제공한다.

## 3. 사용자와 접속

| 역할 | 주요 기능 | 상태 |
|---|---|---|
| 참가자 | 안내·지도·일정·패스·미션·설문·응모·안전 | 확정 |
| 부스 담당자 | 부스 등록·공동 관리·QR 출력·현황·운영본부 문의 | 확정 |
| 행사 운영본부 | 공간·부스·콘텐츠·미션·설문·추첨·현장 대응·통계 | 확정 |
| 플랫폼 운영사 | 행사 개설·재사용·설정·계정·권한 | 확정 |

### 접근 구조

- 확정: 참가자와 관리자의 접속 용도를 분리한다.
- 확정: 부스는 관리 전용 QR와 공통 비밀번호로 여러 기기에서 동시 관리한다. 참가자 인증 QR와 분리한다.
- 확정: 운영본부도 여러 명이 동시에 관리한다.
- 추천: 운영본부는 초대받은 개인 계정으로 접속하고 역할별 권한을 부여한다.
- 추천: 부스 담당자는 행사별 등록 링크에서 존을 선택해 신청하고 승인 후 공개한다.
- 미결정: 운영본부 로그인 제공자·추가 인증, 부스 등록 초대코드, 공통 비밀번호 초기화 절차.
- 운영 계정·담당 연락처는 참가자 설문 원칙과 구분되는 운영상 정보다. 수집 항목과 동의는 별도 확정한다.

## 4. 참가 패스와 기록 유지

### 확정

- 참가 시 개인정보 입력을 요구하지 않는다.
- 자동 발급한 임의 참가 패스에 부스·미션 기록을 연결한다.
- 같은 기기·브라우저 사용을 안내한다.
- 복구 코드·복구 QR·다른 기기 연결·기록 복구 기능은 제공하지 않는다.
- 브라우저 데이터 삭제, 기기·브라우저 변경 시 기록 연결이 어려움을 사전 안내한다.

### 추천

- 안내 열람만으로 패스를 만들지 않고, 첫 인증 등 기록이 필요한 시점에 생성한다.
- 참가 기록·설문·응모는 서버에 저장하고, 브라우저는 접근 식별자를 보관한다.
- 브라우저 연결이 끊겨도 이미 접수된 응모를 삭제하지 않는다.

### 한계와 미결정

- 임의 식별자와 행동 기록도 결합 방식에 따라 개인정보에 해당할 수 있다. ‘설문 전 개인정보가 전혀 없다’고 단정하지 않는다.
- 한 사람이 여러 패스를 생성하는 일을 완전히 차단하지 못한다.
- 패스 생성 시점·브라우저 저장 및 보안 방식·보관 기간을 설계 단계에서 정한다.

## 5. 행사 개설·재사용·테마

### 확정

- 여러 행사를 개설하고 행사별 기능을 설정한다.
- 행사 개설 시 설문 참여 자격과 추첨 응모 자격을 설정할 수 있다.
- 키비주얼을 등록하고 행사 테마에 반영하는 기능을 포함한다. 상세 디자인은 기능 정리 후 진행한다.

### 추천

- 신규 개설과 기존 행사 선택 복제를 제공한다.
- 지도·존·부스·미션·프로그램·설문 문항·문의 분류 등 설정을 선택 복사한다.
- 참가자·인증·설문 응답·연락처·응모·당첨·메시지·신고 기록은 복사하지 않는다.
- 복제 행사 QR·관리 인증은 새로 발급하고 운영자 접근 권한을 재확인한다.
- 키비주얼 기반 색상 자동 제안 → 미리보기·보정 → 적용. 기능 위치와 가독성·안전 색상은 유지한다.
- 준비·공개·운영·종료·보관 상태와 기능별 마감 시점을 구분한다.
- 테스트 기록은 실제 통계·응모에서 제외한다.

## 6. 존·부스 등록·운영

### 확정

- 운영자가 존을 설계한다. 담당자는 부스 등록 시 존을 선택한다.
- 존은 상시체험 구역이며 참가자 예약·접수를 받지 않는다.
- 등록·인증·통계 단위는 부스다. 체험별 등록·QR·통계는 제외한다.
- 부스별 고정 참가 인증 QR를 다운로드·인쇄할 수 있다.
- 행사 운영자도 부스 내용을 수정할 수 있다.
- 부스 운영 상태는 운영 중·일시 중단·운영 종료로 구분한다.
- 일시 중단·운영 종료 시 QR 인증을 중단한다. 운영 재개 시 기존 QR를 유지한다.

### 추천 등록 항목

| 구분 | 항목 |
|---|---|
| 담당자 작성 | 존, 부스명, 운영 기관, 소개·체험 내용, 운영 날짜·시간 |
| 선택 | 이미지, 권장 연령, 소요 시간, 유의사항 |
| 운영 전용 | 담당자 연락처, 시설 요청 |
| 운영자 지정 | 부스 번호, 지도 위치, 공개·승인 상태 |
| 자동 발급 | 인증 QR, 관리 접근 QR, 인쇄 파일 |

- 추천: 작성 중 → 검토 대기 → 수정 요청/승인/미승인. 승인 상태와 현장 운영 상태를 분리한다.
- 추천: 운영자 수정은 전후 값·수정자·시각 기록, 중요 변경은 담당자 확인 요청.
- 추천: PNG·SVG와 부스명·사용법이 있는 A4 PDF 제공.
- 미결정: 필수 항목, 승인 절차, 담당자 수정의 재승인 범위, QR 재발급 권한.

## 7. 부스 QR 인증·선택 평가

### 확정 흐름

부스 QR 스캔 → 부스·운영 상태 확인 → 별점 선택 후 인증 **또는 평가 없이 인증** → 부스 집계·미션 자동 반영.

- 별점은 필수가 아니다. 낮은 점수나 평가 생략이 참여·미션 인정에 영향을 주지 않는다.
- 같은 패스가 같은 부스를 반복 스캔해도 참여자를 중복 집계하지 않는다.
- 중단·종료 시 별점과 인증을 함께 차단한다. 제출 시점에도 서버에서 상태를 확인한다.
- 평가 없는 인증 후 별점 추가 허용은 추천안이며 최종 확정 전이다.

### 추천 안전장치

- 서버 접수 성공 후에만 인증 완료 표시.
- 연속 클릭·통신 재시도에도 중복 처리하지 않음.
- 참가자 공개 부스 소개와 현장 인증 주소를 분리.
- 고정 QR 공유 가능성을 인정하고 집계 명칭에 ‘인증 기준’을 명시.
- 평가 수정·인증 취소·무효 기록과 응모 영향 처리 규칙은 미결정.

## 8. 참여·평가 집계 기준

| 지표 | 기준 |
|---|---|
| 부스 오늘 참여자 | 그날 해당 부스를 인증한 고유 패스 수 |
| 부스 행사 누적 참여자 | 행사 전체에서 해당 부스를 인증한 고유 패스 수 |
| 존 오늘 참여 인원 | 소속 부스의 오늘 참여자 수 합계. 부스 간 중복 제거 안 함 |
| 존 누적 참여 인원 | 소속 부스의 행사 누적 참여자 수 합계 |
| 행사 고유 인증 참여자 | 행사에서 하나 이상 인증한 고유 패스 수. 별도 지표로 제공 추천 |
| 평가 수·평가율 | 유효 평가 수 및 인증 참여자 대비 비율 |
| 만족도 | 평균 별점과 1~5점 분포를 함께 표시 |

- 같은 사람이 한 존의 부스 3개를 인증하면 존 참여 인원은 3으로 계산한다.
- 일별 참여자 합계와 행사 누적 고유 참여자는 다를 수 있다.
- 인증 수는 현장 실제 방문자·현재 체류·혼잡도와 다르다.
- 확정: 부스 담당자는 자기 부스 현황, 행사 운영자는 전체·존·부스별 현황을 본다.
- 추천: 자동 갱신·마지막 갱신 시각·검색·필터·정렬·기간 비교·내보내기.
- 미결정: 갱신 간격, 운영 중 존 변경 시 과거 집계 귀속, 평가 공개 여부.

## 9. 지도·길찾기

### 확정

- 야외: GPS와 지도·경로 서비스 활용.
- 실내: 건물별 통합 평면도 이미지 한 장에 모든 층을 구분해 표시하고 부스 위치를 등록한다. 참가자 층 선택 기능과 층별 이미지 전환은 제공하지 않는다. 실내 GPS 경로 안내는 하지 않는다.
- 위성지도 위에 운영자가 배치도 이미지를 겹쳐 정렬할 수 있다.
- 건물 입구·위치 조건에 따른 실내 화면 전환, GPS가 끊겨도 실내 화면 유지.
- 건물 밖으로 나온 위치가 안정적으로 확인되면 야외 지도로 복귀하는 방향.

### 추천

- 이미지 위치·크기·회전·투명도·기준점 정렬, 부스·존·출입구·건물 외곽·보행로 별도 등록.
- 입구 거리만으로 퇴장을 판단하지 않는다. 건물 외곽·GPS 정확도·지속 시간·진입/이탈 범위 차이 활용.
- 수동 실내외 전환, 건물 선택, 현장 위치 QR 보조. 층 구분은 통합 평면도 안의 표기로 해결한다.
- 야외에서 실내 목적지 선택 시 건물 입구까지 경로 안내 후 해당 건물의 통합 평면도에서 목적지 부스를 강조한다.
- 일반 지도에 없는 행사장 통로·통행 제한은 별도 경로 데이터로 보완.

### 미결정

지도·위성사진·보행 API 제공사와 결합 허용 조건, 비용·한도, GPS 전환 기준·현장 검증, 이미지 정렬 방식, 접근성 경로 데이터 범위.

- 추천: 통합 평면도에서 목적지 부스 영역으로 확대·이동하고 전체 보기로 복귀할 수 있게 한다. 층명·계단·엘리베이터는 평면도 안에서 확인한다.

## 10. 프로그램 안내

- 확정: 사전 예약 기능 제외. 참가 신청·동반인 예약·좌석 차감·대기·취소 관리 없음.
- 추천: 프로그램 소개·대상·날짜·회차·장소·준비물·참여 방법·외부 신청 링크.
- 추천: 날짜·장소별 검색, 관심 일정 저장, 진행·종료·취소 표시, 장소 지도 연결.
- 확정: 미션 QR 확인은 해당 부스 인증으로 대체. 독립적인 미션·프로그램 인증 QR을 초기 범위에 추가하지 않는다.
- 미결정: 프로그램 엑셀 일괄 등록, 일정 변경 공지 연계 세부 방식.

## 11. 미션

### 확정

- 운영자가 개설·공개한 미션을 바로 보고 수행한다.
- 모집·정원·참가 신청·시작 버튼 없음.
- 부스 QR 인증으로 관련 미션 조건 자동 반영, 별도 미션 QR 없음.
- 여러 유형의 미션 지원을 지향한다.

### 추천 조건

지정 부스 인증, 서로 다른 부스 N개, 특정 존의 부스 N개, 여러 존 탐방, 퀴즈, 사진·글 제출.

- 모두 달성 또는 조건 중 N개 달성 조합.
- 수행 기간 안의 기록은 미션 열람 전 기록도 인정.
- 하나의 인증을 여러 미션에 반영.
- 제출 검토형은 진행 중·검토 대기·완료·재제출 요청 상태.
- 미결정: 첫 버전에 넣을 세부 유형, 검토 담당·기준, 사진 공개 여부·보관, 공개 후 조건 변경.

## 12. 전체 설문·응모

### 확정

- 참가자용은 행사 전체 설문 하나. 부스별 설문은 만들지 않는다.
- 설문 원문 붙여넣기로 질문 자동 구성 후 수정·미리보기.
- 개설 시 표준양식을 선택하면 해당 문항을 자동 추가.
- 만족도·탄소·지역경제·추첨 응모 문항 묶음 제공.
- 설문 단계에서 연락처 등 필요한 참가자 개인정보 수집.
- 설문 참여 자격과 추첨 응모 자격을 행사 개설 시 설정.
- 동일 연락처는 추가 응모·중복 당첨 제외. 앞선 참가자별 동일 번호 허용안은 폐기.

### 추천 운영 규칙

- 설문 자격: 전체 또는 미션 달성자. 응모 자격: 설문 제출 또는 설문+미션 조건.
- 미션 조건: 지정 미션 모두 또는 N개 달성.
- 같은 번호의 최초 유효 응모 1건 인정. 추가 설문은 접수하되 응모 제외.
- 국가번호·공백·하이픈 등을 포함한 전화번호 정규화 정책 마련.
- 설문과 응모 결과를 구분하고 다른 응모자의 정보는 노출하지 않음.
- 표준 탄소·경제 문항의 단위·응답 구조 유지, 모름·미응답을 0으로 처리하지 않음.
- 설문 참여와 연락처 제공·응모의 분리, 제출 후 수정, 자격 나중 달성 시 자동 응모는 미결정.
- 문자 인증은 초기 흐름에서 제외된 방향. 연락처 소유를 검증하지 않아 오입력·타인 번호 악용 가능성이 있으며 대응 정책이 필요.

## 13. 추첨·모바일 상품권

- 확정: 추첨 후 모바일 상품권 발송 중심. 즉시 실물 보상 수령 흐름은 대체한다.
- 확정: 같은 연락처의 중복 응모·중복 당첨 제외.
- 추천: 상품별 상품권명·금액·수량·예비 당첨 인원·응모 마감 설정.
- 추천: 대상 확정 → 무작위 추첨 → 실행자·시각·대상·결과 기록.
- 추천: 초기에는 외부 상품권 서비스 발송 파일 출력·결과 반영, 이후 API 확장.
- 추천: 발송 준비·요청·성공·실패·재발송 기록. 성공과 실제 수신·사용을 구분.
- 미결정: 참가 패스당 여러 번호 응모 방지 규칙, 상품 간 중복 당첨, 연락처 정정, 예비 당첨 승계·재추첨, 발송 서비스.

## 14. 탄소·사회적 편익·지역경제

### 확정

- 참가자와 부스 운영진에게 초기 등록 대신 설문에서 활동·지출 정보를 받는다.
- 활동 자료로 탄소 및 지역경제 기여를 분석하는 기능을 포함한다.

### 추천 산정·수집

- 참가자: 이동 수단·거리·동승 인원, 지역 내 항목별 지출·숙박·지출 포함 인원.
- 부스 운영진: 부스당 공동 실적 설문, 인력·물품 이동·인쇄·용품 사용, 지역 구매·임차·고용 지출.
- 운영본부: 공통 전력·폐기물·발주 등 행사 전체 자료.
- 배출량과 감축량을 구분. 감축량은 비교 기준이 있는 경우에만 계산.
- 감축량(tCO2e) × 출처가 명확한 탄소 사회적 비용 단가로 사회적 편익 추정.
- 지역 실제 지출·지역 조달·고용 실적 우선. 같은 거래·공동 지출·인력 이동 중복 방지.
- 배출권 가격·사회적 비용·직접 비용 절감은 구분. 지역 지출과 탄소 편익을 단순 합산하지 않음.
- 응답률·자료 출처·배출계수 버전·추정 가정·불확실성 표시.
- 부스 합계는 방문객 수가 아니므로 설문 확대 추정의 모수로 사용하지 않음.
- 미결정: 표준 문항·계수·비교 기준·지역 범위·추정 방법·전문 검토. 초기 결과는 공식 인증으로 표현하지 않음.

## 15. 공지·운영 소통

### 확정

- 참가자 공지는 전체 대상. 특정 존·부스 이용자 대상 발송은 제외.
- 운영자→전체/존별/선택 부스 업무 알림과 부스↔운영본부 메시지.
- 알림에 확인 버튼. 읽음·명시적 확인·업무 완료를 구분.
- 여러 운영본부·부스 담당자가 동시에 관리.
- 부스가 문의 유형을 고르고 내용·사진을 전송, 유형별 데이터를 축적.

### 추천

- 부스별 대화 안에 문의 건을 만들고 후속 대화는 같은 건에 연결.
- 시설·장비/통신·시스템/물품·지원/운영/안전/민원/기타 공통 대분류 + 행사별 세부 유형.
- 유형과 긴급도 구분, 담당자·접수/확인/처리 중/완료 기록.
- 한 부스 담당자가 확인하면 부스 확인 완료로 공유, 확인자·시각 보관.
- 일반·중요·긴급 공지, 예약 발행·게시 종료·지도 링크.
- 미결정: 웹 푸시·소리·화면 닫힘 상태 알림, 확인 목표 시간, 첨부 제한, 주요 알림 수정 시 재확인.

## 16. 안전·날씨·민감 신고

### 확정

- 안전 기본 메뉴, 날씨 정보, 성희롱·불법촬영 신고 기능 포함.

### 추천

- 긴급 연락, 의료실·AED·비상구·집결지, 행동요령, 전체 긴급 공지.
- 기상 관측·예보·특보와 기준 지역·갱신 시각 표시. 지연 경고.
- 날씨는 운영 판단 보조. 중단·대피는 현장 안전계획에 따라 담당자가 결정.
- 신고: 유형·위치·상황·선택 사진, 증거 없이도 접수 가능.
- 성희롱·성폭력·불법촬영은 지정 피해지원 담당자만 열람, 민감 본문을 일반 알림에 노출하지 않음.
- 접수 성공·담당 확인·대응·종결 구분, 미확인 재알림, 열람 이력.
- 급박한 위험에는 112/119·현장 안전본부에 즉시 연락하도록 안내.
- 미결정: 익명 신고의 후속 대화 보안, 선택 연락처 수집 예외, 미성년자 신고 지원, 담당자·대응 시간·기관 연계, 증거·첨부 보관 정책.
- 신고 기능의 실제 운영은 대응 인력·절차 확보가 전제.

## 17. 언어·홈페이지 연동

### 확정

- 타 언어는 Chrome 페이지 번역 사용 방법 안내.
- 아임웹 등 제작 도구 홈페이지와 연동.

### 추천

- 메뉴·버튼 검토 번역, 콘텐츠 번역 초안 생성·검토·저장·재사용. 원문 수정 시 갱신 표시.
- 안전·동의 문구 검토. 연락처·민감 신고를 일반 번역 API에 자동 전송하지 않음.
- 공개 승인 콘텐츠 API와 삽입 위젯: 존·부스, 일정, 지도, 공지, 참여 링크.
- 개인 참여는 플랫폼 최상위 페이지로 연결해 동일 브라우저 기록 유지.
- 미결정: 번역 제공사·비용·검토 범위, 홈페이지 도구/요금제의 삽입 허용·높이·모바일 호환·동기화 지연.

## 18. 화면 목록 초안

| 역할 | 메뉴 |
|---|---|
| 참가자 | 홈 / 프로그램 / 미션 / 안전 / 내 참여 |
| 부스 담당자 | 현황 / 부스 정보 / 인증 QR / 운영본부 소통 / 운영 상태 / 종료 실적 설문 |
| 행사 운영본부 | 대시보드 / 공간·부스 / 콘텐츠 / 미션·설문 / 추첨·지급 / 소통·대응 / 안전 / 보고서 / 설정 |
| 운영사 | 행사 목록·개설·복제 / 행사별 관리 진입 / 권한 / 서비스 설정·지원 |

- 참가자 하단 메뉴의 지도·부스를 프로그램으로 변경한다(사용자 확정). 지도·부스 찾기는 홈 바로가기와 프로그램 상세의 위치 안내에서 접근한다.
- 행사 키비주얼은 사용자가 제공한 제22회 대한민국 청소년박람회 포스터로 디자인 적용 예시를 검토한다. 청록·파랑과 분홍·노랑 강조색을 사용하되 최종 디자인 승인은 별도다.
- 지도·부스 QR는 목적 화면으로 직접 연결한다.
- 상세 와이어프레임은 일부만 설명한 상태이며 전 화면 검토 완료가 아니다.
- 상세 디자인은 키비주얼과 접근성·현장 가독성을 반영해 별도로 검토한다.

## 19. 공통 품질·운영 요구 추천

- 통신 재시도에도 인증·응모·추첨·발송 중복 방지.
- 운영 중단·마감·권한은 서버에서 확인, 동시 편집 충돌 방지.
- 오프라인에는 저장된 안내·실내 지도 열람, 갱신 시각 표시. 인증·응모는 서버 확인 후 완료.
- 안전 신고 전송 실패 시 즉시 전화 대안 표시. 민감정보의 기기 임시 저장 최소화.
- 참가자·행사·부스 간 권한 침범 차단, 접근·다운로드·수정 이력.
- 개인정보 수집 동의, 만 14세 미만 법정대리인 동의·확인 범위, 신고 예외, 보관·삭제 기준은 최신 기준으로 별도 검토.
- 1만 명 체류를 앱 1만 동시 접속으로 간주하지 않음. 실제 접속·초당 인증·지도/API 사용량 목표를 정해 부하 검증.
- 외부 서비스 키·호출 한도·장애 시 대안, 데이터 백업·복구·보관·모니터링 설정.
- 법적 검토·외부 서비스 계약·성능 검증 완료를 주장하지 않음.

## 20. 초기 범위·제작 순서 제안

사용자가 확정한 기능을 임의로 제외하지 않는다. 아래는 출시 확정 범위가 아닌 제작 의존 순서다.

1. 행사·권한·존·부스 등록 및 공동 관리.
2. 패스·부스 QR 인증·선택 평가·부스/존 실시간 집계.
3. 지도·일정·공지·미션 및 참가자 이용 흐름.
4. 설문 표준양식·자격·연락처 중복 제외·추첨·발송 결과.
5. 운영 소통·안전·날씨·권한별 신고 대응.
6. 홈페이지·번역·탄소/경제 분석·보고서 통합 및 현장/부하 검증.

공통 보안·개인정보·다국어·안전 설계는 마지막 단계로 미루지 않는다.
