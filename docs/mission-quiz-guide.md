# 퀴즈형·설문형 미션 사용 안내

작성: 2026-11-04. 이 문서는 로컬 작업본의 기능을 설명한다. GitHub push와 Render 배포는 아직 수행하지 않았다.

## 1. 이번에 포함한 범위

사용자는 제안한 퀴즈 유형·자료·진행 방식을 모두 포함하고 설문형 미션도 제공하도록 요청했다. 이어서 다음 운영 기준을 선택했다.

- 기본 완료 기준: 필수 문항을 모두 응답하고 필요한 정답 개수 달성. 새 퀴즈의 기본값은 전부 정답이며 운영자가 조정할 수 있다.
- 팀 구성: 참가자가 팀을 만들고 코드로 합류하는 방식과 랜덤 팀 배정을 함께 제공.
- 기본 학습 설정: 힌트 선택 제공, 해당 문항 제출 후 해설, 재도전 횟수 제한 없음.

### 퀴즈 문항 9종

| 유형 | 작성 방법 | 참가자 답변·채점 |
|---|---|---|
| OX | 문제와 O/X 정답 선택 | O 또는 X 선택 |
| 단일 선택 | 보기 작성 후 정답 하나 선택 | 보기 하나 선택 |
| 복수 선택 | 보기 작성 후 정답 여러 개 선택 | 선택한 보기 전체가 정답 집합과 일치해야 정답 |
| 단답 | 허용 정답을 한 줄에 하나씩 작성 | 앞뒤 공백·대소문자·일반적인 유니코드 표현 차이를 정규화해 비교 |
| 빈칸 완성 | 빈칸 이름과 각 빈칸의 허용 정답 작성 | 모든 빈칸이 맞으면 해당 문항 정답 |
| 짝 맞추기 | 왼쪽 항목과 연결할 정답 작성 | 각 항목의 짝을 선택. 오른쪽 보기는 순서를 섞어 제공 |
| 순서 배열 | 항목을 정답 순서대로 배치 | 위·아래 버튼으로 순서 구성. 드래그 없이도 조작 가능 |
| 상황 선택 | 상황 설명, 행동 보기, 정답 작성 | 행동 하나 선택. 분기형에서는 다음 문항과 연결 가능 |
| 사진 속 위치 | 이미지와 보기별 구역, 정답 구역 지정 | 사진의 위치를 누르거나 이름이 붙은 구역을 선택 |

복합 문항인 빈칸·짝·순서는 문항 전체가 맞아야 1개 정답으로 센다. 부분 점수나 시간 점수는 사용하지 않는다.

### 문제 자료

- 텍스트, 사진·그림, 음성, 영상, 현장 관찰 안내를 문항에 붙일 수 있다.
- 이미지: PNG/JPEG/WebP. 음성: MP3/WAV/OGG. 영상: MP4/WebM. 파일 하나당 최대 4MB.
- 이미지 설명 또는 음성·영상의 대체 설명을 작성한다. 현장 관찰형에는 무엇을 어디에서 확인할지 적는다.
- 사진 위치 퀴즈는 보기별 구역을 이미지 위에서 끌어 지정하거나 왼쪽·위·너비·높이 비율로 입력한다.
- 업로드 파일을 앱에서 재생한다. 외부 영상 페이지 삽입이나 영상 변환·압축은 제공하지 않는다.

### 진행 방식 6종

| 방식 | 동작 |
|---|---|
| 한 문제 | 하나의 문항으로 구성 |
| 문제 묶음 | 여러 문항을 한 화면에서 응답 |
| 단계별 공개 | 현재 문항을 통과하면 다음 문항 공개. 응답 완료 기준을 선택한 퀴즈와 설문은 응답 후 다음 단계로 이동 |
| 무작위 출제 | 문제은행에서 설정한 개수 출제. 시작 시 서버가 배정하며 재접속·새로고침해도 같은 문항 유지 |
| 답변에 따른 분기 | OX·단일 선택·상황 선택의 보기마다 뒤의 문항 또는 종료로 연결. 뒤로 돌아가는 순환 분기는 허용하지 않음 |
| 팀 협력 | 팀원들이 서로 다른 문항에 답하고 정답을 합산. 팀 완료 시 참여 중인 팀원 모두 완료 |

진행 방식은 미션당 하나를 선택한다. 여러 문항 유형과 자료를 같은 미션 안에서 섞을 수 있다. 설문형은 개인 응답으로 관리하므로 팀 협력 대신 나머지 5가지 진행 방식을 사용한다.

분기형은 짧은 경로에서도 달성할 수 있는 정답 개수를 설정해야 한다. 경로를 끝냈지만 완료 기준에 미달했다면 처음부터 다시 풀 수 있다. 문항별 제출 횟수 제한을 설정했다면 경로를 다시 시작해도 사용한 횟수는 초기화되지 않는다.

## 2. 운영자가 만드는 순서

1. 운영본부 → **미션·설문 → 미션 추가**에서 완료 조건을 **퀴즈 · 다양한 문항** 또는 **설문 응답**으로 선택한다.
2. 진행 방식과 완료 기준을 선택한다. 퀴즈는 필요한 정답 개수, 문항별 제출 횟수(0은 무제한), 힌트, 해설 시점을 설정한다.
3. 문항을 추가하고 문제·보기·정답·자료를 입력한다. 문항을 위·아래로 이동해 순서를 바꿀 수 있다.
4. **참가자 문항 미리보기**로 입력 화면을 확인한다. 미리보기는 답안 제출이나 참가 기록을 만들지 않는다.
5. 비공개로 저장해 점검한 뒤 미션을 공개한다. 공개 후 문항·정답·완료 기준·진행 방식·팀 설정은 잠긴다. 제목과 설명은 수정할 수 있다.

기존 단답형 미션은 그대로 동작한다. 이미 공개한 기존 퀴즈를 새 구조로 강제 변환하지 않는다. 기존 부스·존 인증과 글 제출·운영자 검토도 계속 사용할 수 있다.

## 3. 팀 협력 운영

운영자는 **팀 코드 참여 + 랜덤 배정**, **팀 코드 참여만**, **랜덤 배정만** 중 선택한다. 기본값은 두 방식을 함께 제공하며, 팀 정원 기본값은 4명(2~20명 설정 가능)이다.

- **코드 참여:** 참가자가 팀 이름을 정해 만들고 팀 참여 코드를 동료에게 전달한다. 같은 행사·같은 미션의 코드로만 합류할 수 있다.
- **랜덤 배정:** 참가자가 랜덤 팀 참여를 누르면 정원이 남고 풀이를 시작하지 않은 랜덤 팀 중 하나에 무작위 배정한다. 대기 팀이 없으면 새 랜덤 팀을 만든다. 코드 초대 팀에는 무작위로 배정하지 않는다.
- **참여 인원:** 2명 이상 모이면 답안을 제출할 수 있다. 첫 답안 제출 전에는 합류하거나 팀에서 나갈 수 있다. 첫 제출 후 팀 구성이 확정된다.
- **공동 답안:** 각자가 답하고 싶은 문항만 제출한다. 다른 팀원의 정답은 유지되며 공동 완료에 반영된다. 다른 팀원의 저장으로 화면이 오래되면 갱신 후 다시 제출한다.
- **현황 갱신:** 미션 창의 팀 현황 갱신 버튼으로 팀원·공동 답안을 확인한다. 실시간 채팅·웹 푸시·자동 팀 재편성은 포함하지 않는다.

참가 패스는 기존과 동일하게 현재 기기·브라우저에 연결된다. 별도의 이름·연락처 수집 없이 팀원을 ‘참가자 1, 2…’로 표시한다.

## 4. 설문형 미션과 결과

설문형 미션에는 단일 선택, 복수 선택, 주관식, 만족도·평가, 숫자 응답을 넣을 수 있다. 정답 없이 필수 응답을 마치면 완료된다. **행사 전체 설문·추첨 응모와는 별도**이며, 설문형 미션 자체에는 연락처·추첨 입력란이 없다.

미션 목록의 **퀴즈·설문 결과**에서 참여/완료 건수와 문항별 결과를 확인한다. 팀 미션은 팀 수와 완료 참가자 수를 구분한다. 선택 문항은 보기별 응답 수, 평가·숫자는 평균/합계, 주관식은 응답 내용을 제공한다(주관식 조회는 최대 200건). 권한은 행사 총괄·콘텐츠·설문 담당자로 제한한다.

응답은 암호화해 저장한다. 행사 설정의 기존 개인정보 삭제 절차는 행사 전체 설문뿐 아니라 설문형 미션의 응답 원자료도 삭제하며, 완료 기록은 유지한다. 원자료를 삭제한 참가 기록은 다시 수집하지 않는다. 내보낸 파일과 백업의 삭제는 기존과 같이 별도 관리한다.

## 5. 연결·검증 범위

- 정답·정답 영역·분기 조건은 서버에서 판정한다. 아직 해금되지 않은 문항, 정답 키, 공개 시점 전 해설은 참가자에게 전달하지 않는다.
- 무작위 문항 배정·답안·제출 횟수는 서버에 저장한다. 동일 제출 재시도는 중복 횟수로 세지 않으며, 완료 기록은 이후 오답으로 되돌리지 않는다.
- 팀 생성·합류·무작위 배정은 트랜잭션에서 처리해 정원 초과와 다른 행사 자료 연결을 막는다.
- 문항·보기·힌트·자료 설명은 기존 영어 번역 검토 흐름과 연결한다. 제출값은 번역된 글자가 아닌 원래 보기 ID를 사용한다. 정답과 정답이 포함될 수 있는 해설은 자동 외부 번역 대상에서 제외한다.
- 검사: 서버 전체 60개, GPS 9개, 기존 8종에 퀴즈 검사를 추가한 브라우저 9종 모두 통과. 임시 DB·가상 참가자만 사용했다.
- 실제 행사 현장 사용성·대규모 접속·Render의 영속 저장·외부 공급자 실키 검증은 기존 후속 과제로 남아 있다.
